# Проверка перед слиянием

```sh
pnpm verify
```

Это `typecheck`, `test`, `build`, `lint` — **ровно то и в том
порядке**, что гоняет CI.

## Почему это записано отдельной командой

25.10 основная ветка простояла красной шесть коммитов. Каждый из них
я проверял перед слиянием и каждый раз видел «21 из 21» — потому что
гонял `test typecheck lint` и **ни разу `build`**. Падала
production-сборка кабинета, то есть ровно тот шаг, которого в моей
привычке не было.

Заметил это не я, а зона развёртывания, пришедшая за образом: гейт
проверок не дал собрать образ на красном коммите, и выкатывать
оказалось нечем.

**Набор, который помнят, расходится с набором, который гоняют.**
Поэтому он теперь команда, а не память.

## Почему шаги последовательно, а не одной `turbo run`

`turbo run typecheck test build lint` одной командой запускает всё
вместе: 23 задачи, среди них тяжёлые сборки webpack. На восьми ядрах
это перегрузка, и под ней падает сбор файлов проверок — краснеет то,
что в CI зелено.

CI гоняет шаги **по очереди** (`pnpm typecheck`, затем `pnpm test`,
затем `pnpm build`). Проверка обязана воспроизводить проверяемое, а не
более тяжёлый случай: иначе она краснеет не по делу, и её перестают
запускать.
