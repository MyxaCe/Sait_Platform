## Терминал = White Label-поставщик торговой страницы (решение пользователя 2026-07-25)

**Целевая модель** (монорепо ОТКЛОНЁН пользователем — и это правильно для этой роли): терминал — независимая система-поставщик; N страновых сайтов потребляют одну и ту же торговую страницу; настройки каждого сайта (бренд, цвета, логотип, инструменты) живут в НАШЕЙ CMS per-site; терминал в рантайме красится в бренд конкретного сайта (CSS-токены RGB-каналами → без пересборки, одна сборка на все бренды).

**Следствия для нас** (фиксируются в ADR-023 после созвона):
- CMS → мульти-тенантность: коллекция sites, бренд/контент per-site, контракт `/v1/cms/*?site=` — следующий крупный этап CMS
- Auth/SSO-сервис становится обязательным (один терминал × много сайтов — триггер ADR-017 срабатывает)
- Токены `@broker/ui/tokens.css` — публикуемый артефакт (контракт темизации для терминала)

**Повестка созвона с командой терминала:**
1. **Способ поставки страницы**: поддомен per-site (trade.site-x) vs iframe в кабинете vs widget-скрипт; если iframe — `frame-ancestors` под origins сайтов (грабли B-014) и postMessage-протокол
2. **Темизация в рантайме**: договориться о контракте — терминал принимает идентификатор сайта (`?site=` / поддомен), читает `GET /v1/cms/brand` (+ наши CSS-токены), применяет без пересборки; что у них сейчас с темизацией
3. **Auth**: протокол SSO (кабинет сайта выдаёт короткоживущий токен → терминал проверяет); наш план — выделенный Auth-сервис, нужен их формат ожиданий
4. **Данные**: их WS-протокол котировок/ордеров (их бэкенд остаётся их сервисом); нужна ли сайтам подписка на тот же фид (наш FeedDriver — совместимость форматов)
5. **Локализация**: как терминал переводится; passthrough локали сайта (`?locale=`)
6. **Артефакты после созвона**: доступ к репо (для оценки контракта, не для слияния), схема WS-протокола, контакт интеграции

## 🚀 Установщик новой страны (задание пользователя 2026-07-25, будущее)

Цель: **новый страновой сайт разворачивается за минуты, без программиста** («кнопка/команда для владельца»). Состав установщика:
- Вход: slug страны, домены, языки, основа бренда (цвет/логотип/название).
- Автоматика: карточка сайта в CMS + сид контента с базового сайта → env-набор страновой группы (SITE_SLUG, домены, секреты) → docker compose группы (web+cabinet+relay+postgres) на страновом VPS → TLS (Caddy/Let's Encrypt) → регистрация origin'ов (frame-ancestors терминала, вебхук CMS→сайт, JWKS-список) → миграции БД → **автосмоук после подъёма** (health'ы, регистрация тестового пользователя, тикер из MDS, SSO в терминал) с человекочитаемым отчётом «✅ страна запущена».
- Форма: CLI `provision-site` + (идеал) кнопка «Новый сайт» в админке CMS.
- Предпосылки (строго в этом порядке): 1) CD на VPS — фундамент; 2) мульти-тенантная CMS (per-site контент) — без неё нечего сидировать; 3) установщик.
