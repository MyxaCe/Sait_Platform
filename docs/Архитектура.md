# Архитектура

## Монорепозиторий (Turborepo + pnpm)

```
apps/
  web/            маркетинговый сайт — Next.js 14 App Router
  cabinet/        (будущее) личный кабинет — отдельный Next.js на my.*
  terminal/       (будущее) веб-терминал — SPA
packages/
  ui/             дизайн-система: atoms → molecules → organisms, токены тем
  realtime/       WebSocket-ядро котировок (драйверы mock / socket.io)
  utils/          форматтеры (Intl): валюты, цены, проценты, даты
  config/         общие tsconfig + tailwind-preset
```

Правило композиции: страницы `apps/web` собираются из organisms/layout дизайн-системы; atoms напрямую в страницах не используются. UI-организмы **не содержат текстов** — все подписи приходят пропсами (см. [[Решения (ADR)#ADR-012]]).

## Ключевые паттерны

### Темизация
Все цвета — только CSS-переменные в RGB-каналах (`--accent: 212 164 55`) из `packages/ui/src/tokens/tokens.css`. Тёмная тема — по умолчанию, светлая через `[data-theme='light']` (next-themes). Благодаря этому смена бренда/темы не требует пересборки — фундамент White Label.

### Realtime (`packages/realtime`)
- Интерфейс `FeedDriver` (connect / subscribe / unsubscribe / disconnect); реализации: **mock** (random walk, батчи 800 мс) и **socket.io** (reconnect + jitter, восстановление подписок). Выбор по `NEXT_PUBLIC_WS_URL` — не задан → mock.
- `RealtimeService` — singleton, подписки по счётчику ссылок (N виджетов на символ = 1 подписка). `connect(customDriver?)` — точка внедрения для тестов.
- Zustand-стор инициализируется статичным снапшотом `SYMBOL_UNIVERSE` → SSR отдаёт HTML с ценами (SEO), живой фид гидрируется поверх без mismatch/CLS.

### i18n (next-intl v4)
- Локали `ru` (default, без префикса) и `en` (`/en/...`), `localePrefix: 'as-needed'`, **`localeDetection: false`** (см. [[Журнал багов#B-005]]).
- Все маршруты под `app/[locale]/`; навигация только через `@/i18n/navigation` (Link/usePathname/redirect).
- Контент — per-locale в data-файлах (`getX(locale)`), слаги общие; UI-строки — `messages/{ru,en}.json`.
- Zod-сообщения форм = **ключи** namespace `validation`, переводятся при отображении (сервер и клиент разделяют одну схему).
- ⚠️ Грабли: `setRequestLocale` строго ДО `notFound()`; обязателен `app/[locale]/not-found.tsx` (см. [[Журнал багов#B-006]], [[Журнал багов#B-007]]).

### Формы и BFF
`react-hook-form + zodResolver` → `POST /api/leads/*` (route handlers): повторная валидация той же схемой, honeypot-поле `website`, in-memory rate-limit (`lib/rate-limit.ts`, замена на Redis при масштабировании). Ключи ошибок сервер отдаёт языконезависимо.

### PWA (Serwist)
`app/sw.ts`: precache статики, `defaultCache`, офлайн-фолбэк `/offline`; котировки не кешируются. SW отключён в dev. `manifest.ts` + иконки + `InstallPWAButton` (beforeinstallprompt / iOS-инструкция / manual).

### SEO
`app/sitemap.ts` (все URL из тех же источников, что и `generateStaticParams`), `robots.ts`, JSON-LD: FinancialService (root), NewsArticle, Article, BlogPosting, FAQPage, BreadcrumbList. `lib/site.ts` — `SITE_URL` из `NEXT_PUBLIC_SITE_URL`.

## Инфраструктура

- **Локально**: `docker compose up db` (Postgres для лидов/outbox) + `pnpm dev`; полный стек — `docker compose --profile full up` (web standalone + relay). Без DATABASE_URL формы работают на MemoryLeadStore (dev/e2e).
- **Данные сайта (ADR-018)**: Postgres `broker_site` — таблицы `leads` (source of truth, unique email для account-opening) и `outbox`; схема в `db/init/001_init.sql`.
- **Релей** `apps/relay`: outbox → шина платформы (`FOR UPDATE SKIP LOCKED`, backoff 5s→1h, at-least-once); `BUS_URL` не задан → публикация в лог. Часть failure domain сайта, не отдельный сервис.
- **Прод**: VPS, образы из `docker/web.Dockerfile` (Next standalone, `BUILD_STANDALONE=1`) и `docker/relay.Dockerfile`; CI — GitHub Actions.
- ISR-кеш при **одном** инстансе — файловая система, ок. При масштабировании — общий `cacheHandler` (Redis), см. [[Технический долг]].
- Error tracking: общий GlitchTip (хостит команда CRM) — [[Решения (ADR)#ADR-014]].

## Будущая экосистема

Кабинет — отдельное Next.js-приложение на поддомене (НЕ Module Federation): изоляция сбоев, независимый деплой. SSO: access JWT (15 мин, в памяти) + refresh httpOnly cookie `Domain=.broker.com`, ротация. Терминал переиспользует `@broker/realtime` целиком. Header из `@broker/ui` имеет слот userArea.
