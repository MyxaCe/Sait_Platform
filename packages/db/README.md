# Миграции схемы базы сайта

Единственный источник схемы (`WEB-31`). В `db/init` её больше нет —
там лежит объяснение, почему.

## Имена

Префикс — метка времени в миллисекундах: именно её разбирает механизм.
С любым другим видом он печатает «Can't determine timestamp» на каждом
прогоне, а **постоянное предупреждение опаснее отсутствующего** — оно
приучает не читать и однажды скроет настоящее сообщение. Пробовал
читаемый `ГГГГММДДЧЧММСС`: не разбирается, предупреждение остаётся.

Читаемость держится на суффиксе и на этой таблице. Соответствие
прежним именам из `db/init`, чтобы ссылки в разборах оставались
находимыми:

| было | стало | дата |
| --- | --- | --- |
| `001_init.sql` | `1785542460000_init.sql` | 2026-08-01 |
| `002_cabinet.sql` | `1785542520000_cabinet.sql` | 2026-08-01 |
| `003_cabinet_v2.sql` | `1791244980000_cabinet_v2.sql` | 2026-10-06 |
| `004_trading.sql` | `1791245040000_trading.sql` | 2026-10-06 |
| `005_drop_balance_default.sql` | `1792800300000_drop_balance_default.sql` | 2026-10-24 |

**В каталоге миграций не должно быть ничего, кроме `.sql`** — механизм
пытается разобрать метку у каждого файла. Поэтому это описание лежит
на уровень выше.

Содержимое при переносе **не менялось**: перенос отделён от правок
нарочно, чтобы в разборе было видно, что механизм ничего не переписал.
