# Здесь больше нет схемы

Схема базы сайта живёт в `packages/db/migrations` и применяется
механизмом миграций (`WEB-31`). В этом каталоге её **нарочно нет**.

## Почему каталог остался

Его монтирует `docker-compose.yml` в `docker-entrypoint-initdb.d`.
Postgres выполняет оттуда только `.sql`, `.sql.gz` и `.sh`; этот файл
он не тронет. Каталог оставлен, чтобы монтирование не сломалось, а
объяснение лежало там, куда придёт тот, кто станет искать схему.

## Почему схему отсюда убрали

`docker-entrypoint-initdb.d` выполняется **только при первом создании
базы**. На уже работающем сервере файл отсюда не применится сам — и
именно так `005_drop_balance_default.sql` пролежал неприменённым,
причём **узнать об этом было нечем**: «схема актуальна» и «схема
неизвестна» выглядели одинаково.

Оставить файлы здесь и завести миграции значило бы получить **два
источника одной схемы**: на свежей базе они выполнились бы дважды, а
расходиться начали бы молча. Источник теперь один.

## Как поднять локально

```sh
docker compose up -d db
pnpm --filter @broker/db migrate
```

Второй шаг обязателен: пустая база после первого шага — это пустая
база, а не «всё готово».
