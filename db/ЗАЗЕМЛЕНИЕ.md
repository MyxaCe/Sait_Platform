# Заземление живой базы под механизм миграций (WEB-31)

Разовая операция. Исполняет зона `deploy`, **по шагам**, сверяя
наблюдаемое после каждого. У каждого шага назван ожидаемый результат —
не «успех», а состояние.

## Почему это нужно

Файлы `001`–`004` выполнились при создании базы (`db/init` →
`docker-entrypoint-initdb.d`), `005` — **нет**, и узнать об этом было
нечем. Механизм должен узнать, что четыре уже применены, иначе он
попытается применить их заново.

## Шаги

### 1. Спросить состояние — ожидается «НЕИЗВЕСТНО», код выхода 3

```sh
pnpm --filter @broker/db migrate:status
```

Ожидаемый вывод содержит слово `НЕИЗВЕСТНО`. Если вместо него
печатается список применённых — **остановитесь и скажите**: значит
таблица учёта уже есть, и заземление либо сделано, либо база не та.

### 2. Объявить применённым то, что применено

```sql
CREATE TABLE IF NOT EXISTS pgmigrations (
  id     serial PRIMARY KEY,
  name   varchar(255) NOT NULL,
  run_on timestamp    NOT NULL
);

INSERT INTO pgmigrations (name, run_on) VALUES
  ('1785542460000_init',       now()),
  ('1785542520000_cabinet',    now()),
  ('1791244980000_cabinet_v2', now()),
  ('1791245040000_trading',    now());
```

**`1792800300000_drop_balance_default` сюда НЕ входит** — он и есть
тот, который не применился. Объявить его применённым значило бы
записать неправду в учёт, и дальше никто бы этого не нашёл.

### 3. Спросить снова — ожидается «ОТСТАЛА», код выхода 1

```sh
pnpm --filter @broker/db migrate:status
```

В выводе должно стоять ровно одно `ОТСУТСТВУЕТ
1792800300000_drop_balance_default`. Если отсутствующих больше —
**остановитесь**: значит применено не то, что мы думаем.

### 4. Применить недостающее

```sh
pnpm --filter @broker/db migrate
```

### 5. Проверить СОСТОЯНИЕМ, а не сообщением

```sh
pnpm --filter @broker/db migrate:status   # код выхода 0, «применено 5 из 5»
```

И отдельно — то, ради чего всё затевалось:

```sql
SELECT coalesce(column_default, 'НЕТ УМОЛЧАНИЯ')
  FROM information_schema.columns
 WHERE table_name = 'demo_accounts' AND column_name = 'balance_cents';
```

Ожидается `НЕТ УМОЛЧАНИЯ`. Это проверка самого факта, а не отчёта о
нём: механизм мог отчитаться об успехе и не сделать ничего — ровно
такие отчёты мы и перестали принимать.

## После заземления

Приложения начинают отказываться стартовать на схеме, которой не
знают. Это ожидаемо и есть цель: «схема неизвестна» перестаёт быть
состоянием, в котором можно работать.
